CICADOS

Plateforme de Réservation & Gestion pour Bar à Jeux

Présentation du projet de fin d'études — Session 2026

01. INTRODUCTION
Contexte & Besoin Métier

📌 Le Contexte

  • Activité : Bar à jeux de société et espace événementiel.
  • Organisation : Soirées jeux, tournois et réservations de tables.
  • Enjeu : Offrir une expérience fluide aux joueurs et automatiser la gestion.

🎯 Le Besoin

  • Gestion Manuelle : Risques élevés d'erreurs et de double-réservation.
  • Visibilité Jeux : Accès difficile au catalogue de jeux à l'avance.
  • Gain de Temps : Inquiétude sur la charge de gestion sur place.
01. INTRODUCTION
La Solution Cicados

⚡ Web App Fullstack

  • Frontend : React (Vite) ultra-réactif.
  • Backend : API REST Express moderne.
  • BDD : Base MySQL structurée et sécurisée.

📅 Réservation Sans Conflit

  • Vérification temps réel : Moteur de contrôle des créneaux.
  • Gestion capacités : Adaptation selon le nombre de personnes.
  • Confirmation : Retours d'état immédiats pour le client.

🎲 Catalogue Interactif

  • API BGG : Synchronisation avec BoardGameGeek.
  • Fiches complètes : Visuels, avis, durées et joueurs.
  • Mode Secours : Sauvegarde locale JSON anti-panne.
02. LA CONCEPTION
Préparation & Choix de Conception

1. Méthodologie Agile

  • User Stories : Découpage fonctionnel complet.
  • MoSCoW : Priorisation stricte des fonctionnalités.
  • Sprints : Développement incrémental orienté MVP.

2. UX & Wireframes

  • Parcours Utilisateur : Réservation fluide en 3 clics.
  • Design System : Tailwind CSS v4 réactif.
  • Interface Mobile : Approche responsive first.

3. Modélisation BDD

  • MCD / MLD : Conception relationnelle propre.
  • Normalisation : Absence de redondances.
  • Contraintes SQL : Clefs étrangères et intégrité.
03. LE DÉVELOPPEMENT
Fct 1 : Moteur Anti-Conflit de Réservation

🎯 Besoin & 💡 Solution

  • Besoin : Garantir l'absence absolue de double-réservation sur une même table.
  • Pourquoi cette solution : Vérification algorithmique backend lors de chaque tentative.
  • Logique Temporelle : (Start1 < End2) AND (End1 > Start2).

⚠️ Difficulté & ✅ Résolution

  • Difficulté : Traitement des chevauchements de créneaux partiels.
  • Résolution : Requête SQL transactionnelle optimisée avec validation stricte.
  • Résultat : Zéro sur-réservation possible sur l'ensemble de l'établissement.
03. LE DÉVELOPPEMENT
Fct 2 : Catalogue BoardGameGeek (Proxy XML/JSON)

🎯 Besoin & 💡 Solution

  • Besoin : Enrichir les jeux avec visuels et durées sans saisie manuelle.
  • Pourquoi cette solution : Proxy backend Node.js interrogeant l'API externe BGG.
  • Parsing : Conversion du XML natif de BGG en JSON propre pour React.

⚠️ Difficulté & ✅ Résolution

  • Difficulté : Instabilité et latence de l'API externe BGG.
  • Résolution : Parser XML->JSON avec cache local et mode secours JSON.
  • Résultat : Service continu même si BGG est indisponible.
03. LE DÉVELOPPEMENT
Fct 3 : Authentification & Sécurité (Zod / JWT)

🎯 Besoin & 💡 Solution

  • Besoin : Proteger les comptes utilisateurs et l'administration.
  • Pourquoi cette solution : Jetons JWT sécurisés et validation d'entrées Zod.
  • Validation Partagée : Mêmes schémas Zod en Frontend et Backend.

⚠️ Difficulté & ✅ Résolution

  • Difficulté : Synchronisation de la session utilisateur sur React.
  • Résolution : Context React d'authentification + Middleware Express centralisé.
  • Résultat : Connexion sécurisée et étanche.
04. POINTS TECHNIQUES
Architecture & Sécurité OWASP

🏗️ Architecture MVC Découplée

  • Frontend : React 19 (Vite), SPA réactive.
  • Backend : Express 5 (API REST), logique métier centralisée.
  • Database : MySQL 8 avec intégrité relationnelle.

🔒 Sécurité (OWASP)

  • Bcrypt : Hachage fort des mots de passe.
  • Injections SQL : Requêtes préparées indispensables.
  • Variables d'env : Fichier .env totalement isolé.
04. POINTS TECHNIQUES
Performance, Accessibilité & i18n

⚡ Performance

  • Vite : Bundler ultra-rapide au démarrage.
  • Composants React : Structure modulaire réutilisable.
  • Zod : Filtrage immédiat des erreurs côté client.

♿ Accessibilité & i18n

  • HTML5 Sémantique : Structure lisible pour la synthèse vocale.
  • i18n Multilingue : Support FR / EN via i18next & DeepL.
  • Tailwind CSS v4 : Design parfaitement responsive.
05. CONCLUSION
Bilan, Difficultés & Évolutions

🎓 Ce que j'ai appris

  • Maîtrise complète de la chaîne Fullstack (React/Node/MySQL).
  • Conception d'algorithmes métier complexes (réservation/créneaux).
  • Gestion proactive des pannes d'API tierces.

🧗 Difficultés

  • Gestion rigoureuse du temps sur les Sprints.
  • Parsing XML et traitement des flux de données externes.

🔮 Évolutions

  • Paiement d'acompte en ligne via Stripe.
  • Notifications SMS / Email de rappel (Brevo).
  • Recommandations intelligentes de jeux par IA.
