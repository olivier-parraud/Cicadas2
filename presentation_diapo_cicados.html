4. Développement (F1)

Algorithme d'Overlap Temporel & Résolution SQL

16 / 30
La Difficulté Rencontrée
Les Conflits de Chevauchement
  • Cas limites d'intervalles qui se croisent partiellement
  • Une réservation de 14h à 16h entre en conflit avec une demande 15h-17h
  • Risque de collision si deux utilisateurs valident au même instant
  • Nécessité de bloquer immédiatement la création si toutes les tables sont prises
La Résolution Technique
Formule Mathématique & Transaction
  • Formule d'intersection : start_time < newEndTime AND end_time > newStartTime
  • Filtrage SQL excluant les réservations déjà annulées (status != 'CANCELLED')
  • Transaction SQL atomique (START TRANSACTION / COMMIT / ROLLBACK)
  • Code HTTP 400 explicite et levée d'exception immédiate si saturé

4. Développement (F4 Bonus)

Transcodage XML/JSON & Haute Résilience

22 / 30
Deux Défis Majeurs
Restrictions CORS & Panne SQL
  • L'API BGG bloque les appels navigateurs directs (politique de sécurité CORS)
  • BGG renvoie du XML complexe incompatible avec React sans transcodage
  • Si la base de données MySQL tombe, le catalogue afficherait un écran blanc
  • Nécessité de garantir la continuité de service pour les visiteurs
La Résolution Technique
Proxy Edge Node.js & Failover JSON
  • Proxy backend Node.js servant de relais transparent et contournant CORS
  • Transcodage XML vers JSON instantané via la librairie fast-xml-parser
  • Failover automatique : bascule sur le fichier local boardgame-list.json si MySQL échoue
  • Navigation dans le catalogue 100% fonctionnelle même en cas de panne BDD

5. Points Techniques

Sécurisation des Uploads de Fichiers (Multer)

24 / 30
Menaces Réelles
Risques Identifiés
  • Exécution de scripts malveillants (.php / .js maquillés en .jpg)
  • Traversée de répertoire (injection de '../' pour écraser des fichiers système)
  • Déni de service par saturation du stockage serveur (fichiers géants)
  • Fichiers corrompus rendant l'interface instable
Parades Implémentées
Contre-Mesures Multer
  • Liste blanche stricte sur les types MIME (JPEG, PNG, WEBP)
  • Destruction du nom d'origine et renommage unique (Timestamp + UUID)
  • Limite matérielle stricte à 2 Mo par fichier
  • Rejet immédiat avant écriture sur le système de fichiers
Rendu Graphique
Expérience Utilisateur
  • Prévisualisation instantanée (Live Preview) avant validation
  • Feedback immédiat en cas de format invalide ou fichier trop lourd
  • Organisation claire des médias stockés dans le dossier public
